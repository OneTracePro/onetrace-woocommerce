# OneTrace.pro для WooCommerce

Подключает магазин на WooCommerce к [OneTrace.pro](https://onetrace.pro) — платформе данных о клиентах (CDP): заказы, покупатели и согласия на рассылку с сервера, трекер сайта, каталог товаров, виджеты рекомендаций, Web Push и письма магазина через OneTrace. Цепочки брошенной корзины, просмотра без покупки, после покупки и возврата клиентов, рекомендации и прогнозы работают сразу после подключения.

[English version](README.md)

- WordPress 6.6+, WooCommerce 9.0+ (проверено до 11.2), PHP 7.4–8.5; поддерживаются HPOS и блоки корзины и оформления заказа
- Заказы и их статусы отправляются с сервера — их не теряют блокировщики рекламы и закрытые вкладки — через очередь с повторами: магазин никогда не ждёт платформу
- Те же события и свойства, что у всех плагинов OneTrace для магазинов

## Что передаётся

| Данные | Когда | Как |
|---|---|---|
| `identify` — email, телефон, имя, город, страна, язык | регистрация, вход, изменение профиля и адреса, оформление заказа | сервер, секретный ключ |
| Согласие на рассылку | галочка при оформлении заказа (классическом и блочном), в форме регистрации и в личном кабинете | сервер, вместе с `identify` |
| `order_completed`, `order_paid`, `order_cancelled`, `order_refunded` | заказ оформлен, оплачен (наложенный платёж — когда выполнен), отменён, возврат | сервер, один раз на событие заказа |
| `order_shipped`, `order_delivered` | посылка с трек-номером (WooCommerce Shipment Tracking, Advanced Shipment Tracking, TrackShip) или выполненный заказ без отслеживания; статус «Доставлен» | сервер, один раз на посылку / заказ |
| `add_to_cart`, `remove_from_cart`, `checkout_started` | изменения корзины и страница оформления — для посетителей с cookie трекера или вошедших | сервер |
| `add_to_wishlist`, `remove_from_wishlist` | избранное YITH WooCommerce Wishlist или TI WooCommerce Wishlist — для тех же посетителей | сервер |
| `product_viewed`, просмотры страниц | витрина | трекер в браузере |
| Каталог товаров с `stock` | изменения товаров и остатков (заказы, отмены, возвраты, админка, REST), раз в сутки и кнопка «Выгрузить весь каталог» | сервер, `products.write` |

Заказы гостей без cookie трекера связываются по email: `identify` и события заказа гостя попадают в один профиль.

По умолчанию `product_id` — ID записи. Если каталог и история проекта уже ведутся по артикулам (например, после переезда с другой платформы), выберите **ID товара → Артикул**: события, заказы, каталог и виджеты будут передавать артикул (ID записи — у товаров без артикула).

## Установка

1. Установите **OneTrace для WooCommerce** из каталога плагинов WordPress (**Плагины → Добавить новый**, [wordpress.org/plugins/onetrace-for-woocommerce](https://wordpress.org/plugins/onetrace-for-woocommerce/)) или загрузите `onetrace-for-woocommerce.zip` из [последнего релиза](https://github.com/OneTracePro/onetrace-woocommerce/releases/latest) в **Плагины → Добавить новый → Загрузить плагин**.
2. В проекте OneTrace откройте **Ключи API** и создайте ключ записи (для витрины) и секретный ключ с правом `products.write` (для сервера).
3. В **WooCommerce → Настройки → OneTrace** укажите адрес платформы (домен, по которому вы открываете OneTrace) и оба ключа, нажмите **Проверить подключение**.

Ключи можно хранить не в базе, а в `wp-config.php`:

```php
define('ONETRACE_URL', 'https://cdp.onetrace.pro'); // или домен вашего бренда
define('ONETRACE_WRITE_KEY', 'cdp_wk_…');
define('ONETRACE_SECRET_KEY', 'cdp_sk_…');
```

## Остатки, избранное и «Сообщить о поступлении»

- **Остатки:** у товаров с учётом запасов в каталоге передаётся `stock` (у вариативного — сумма вариаций с учётом запасов); товары без учёта запасов или с разрешёнными предзаказами передаются без него. Платформа использует остаток — нулевой снимает товар с продажи, цепочки «осталось мало» и «снова в наличии» — только с настройкой каталога **Учитывать остатки из API и плагинов**.
- **Избранное:** своего избранного в WooCommerce нет. С [YITH WooCommerce Wishlist](https://wordpress.org/plugins/yith-woocommerce-wishlist/) или [TI WooCommerce Wishlist](https://wordpress.org/plugins/ti-woocommerce-wishlist/) добавление и удаление товаров передаётся с сервера (настройка **Избранное**). С другим избранным отметьте кнопки темы для трекера (1.13.0 и новее) — он отправит события по клику:

  ```html
  <button data-cdp-wishlist="123">В избранное</button>
  <button data-cdp-wishlist-remove="123">Убрать из избранного</button>
  ```

  `123` — ID товара в каталоге: ID записи или артикул при **ID товара → Артикул**.
- **Сообщить о поступлении:** на странице товара не в наличии (у вариативного — когда ни одной вариации нет в наличии) плагин выводит `<div data-cdp-notify="{ID товара}"></div>` после блока добавления в корзину (классические шаблоны и блочные темы). Трекер (1.14.0 и новее) рисует в нём форму; саму форму настраивают в разделе платформы **Сайт → Формы** (вид «Сообщить о поступлении»). Выключается настройкой **Сообщить о поступлении**.

## Отправка и доставка

Платформа показывает службу доставки, трек-номер и ссылку для отслеживания покупателю и ИИ онлайн-чата («где мой заказ?»). Своих посылок в WooCommerce нет, поэтому плагин берёт их из плагинов отслеживания:

- **Плагины отслеживания** — [WooCommerce Shipment Tracking](https://woocommerce.com/products/shipment-tracking/), [Advanced Shipment Tracking](https://wordpress.org/plugins/woo-advanced-shipment-tracking/) и работающий поверх них [TrackShip](https://wordpress.org/plugins/trackship-for-woocommerce/): каждая добавленная к заказу запись отслеживания — одно `order_shipped` с `carrier` (название службы из списка плагина или своя служба), `tracking_number` и `tracking_url` (ссылка службы с номером или своя ссылка). Вторая посылка — новое событие; повторное сохранение заказа ничего не отправляет. Товары частичной отправки передаются, если плагин их хранит (AST PRO).
- **Без отслеживания:** когда заказ становится **Выполнен** или **Отправлен** (статус плагинов отслеживания) — одно `order_shipped` без трек-номера, только если по заказу ещё не отправлялась посылка и в нём есть товары с доставкой.
- **Доставлен:** статус **Доставлен** из AST или TrackShip — `order_delivered`; с TrackShip также его статус отправления «delivered», когда доставлены все посылки заказа. Своего статуса доставки в WooCommerce нет, без этих плагинов событие не отправляется.

Другой плагин отслеживания может передать свои посылки фильтром `onetrace_woocommerce_order_shipments` и сообщить о новой посылке:

```php
add_filter('onetrace_woocommerce_order_shipments', function (array $shipments, WC_Order $order): array {
    foreach (my_tracking_parcels($order) as $parcel) {
        $shipments[] = [
            'carrier' => $parcel->carrier,                // название, которое видит покупатель
            'tracking_number' => $parcel->number,
            'tracking_url' => $parcel->url,
            'shipped_at' => $parcel->shipped_at,          // метка времени или DateTimeInterface
            'estimated_delivery' => $parcel->eta,         // 'ГГГГ-ММ-ДД', необязательно
            'items' => [$orderItemId => 1],               // частичная отправка: ID позиции заказа => количество, необязательно
        ];
    }

    return $shipments;
}, 10, 2);

do_action('onetrace_woocommerce_sync_shipments', $order); // после сохранения посылки
```

Статусы настраиваются фильтрами `onetrace_woocommerce_shipped_statuses` (`completed`, `shipped`) и `onetrace_woocommerce_delivered_statuses` (`delivered`). Оба события подчиняются настройке **Заказы**.

## Письма магазина

Письма магазина — WooCommerce, WordPress (сброс пароля, новый пользователь) и других плагинов, всё, что отправляется через `wp_mail()`, — могут уходить через почтовую интеграцию проекта OneTrace: со статусами доставки и историей в профиле покупателя и пределом писем на получателя платформы. Настраивается в разделе **Письма магазина** платформы (плагин читает его через `GET /api/v1/emails/settings` раз в 5 минут и сразу после сохранения настроек плагина); секретному ключу нужно право **Отправка сообщений вручную** (`messages.send`). В **Настройки → OneTrace → Письма магазина** видно состояние (только для чтения).

- **Письма о заказе по шаблонам OneTrace:** для письма о заказе с включённым шаблоном плагин передаёт данные заказа — номер, ссылку на страницу заказа (Мой аккаунт → заказ, у гостей — страница «Заказ принят»), товары с артикулом, картинкой, ссылкой и опциями, суммы, способ оплаты и доставки, адреса, комментарий покупателя, инструкции оплаты банковским переводом / чеком / при получении, сумму и причину возврата, службу доставки и трек-номер — а также язык покупателя (WPML, Polylang, язык витрины или аккаунта, иначе язык магазина) и имя; OneTrace собирает письмо на этом языке, а магазин своё не отправляет. Письмо магазина передаётся вместе с данными: если шаблон за это время выключили, OneTrace отправит его как есть.
- **Все письма магазина через OneTrace** («relay»): остальные письма уходят такими, какими их сделал магазин, — тема, HTML, текстовая версия, адрес для ответа, имя отправителя и вложения (PDF, PNG, JPEG, GIF, TXT, CSV, ICS; до 5 файлов и 5 МБ). Один запрос на получателя.
- **Письма владельцу магазина и сотрудникам магазин всегда отправляет сам**, даже с включённым «relay», — иначе OneTrace заведёт профили покупателей на адреса сотрудников: все виды `admin_*` (новый, отменённый, неудачный заказ WooCommerce …, уведомления WordPress о новом пользователе и смене пароля), любое письмо на адрес администратора сайта или получателям писем WooCommerce магазину, а также копии Cc / Bcc.
- **Отправлен и доставлен:** таких писем в WooCommerce нет. С включённым шаблоном `order_shipped` / `order_delivered` каждая новая посылка (см. [Отправка и доставка](#отправка-и-доставка)) и доставка отправляют письмо по шаблону в фоне (Action Scheduler, `onetrace_order_email`) — один раз на посылку и один раз на заказ. Письмо **Выполнен** тогда становится письмом об отправке без трек-номера (один раз — тем же, что отправилось бы в фоне) или не отправляется, если у заказа есть посылки: о них покупателю уже написали. Подчиняется настройке **Заказы**.
- **Если OneTrace не принял письмо** — нет почтовой интеграции, исчерпана квота сообщений (402), слишком много писем получателю (429), вложение другого типа или больше предела, платформа не ответила за 5 секунд, нет секретного ключа или права, — **магазин отправляет его сам**, и только тем получателям, которых OneTrace не принял. Ошибка чтения настроек запоминается на минуту (на 10 минут — для ключа без права), чтобы не спрашивать платформу на каждое письмо.

| Письмо WooCommerce | Вид |
|---|---|
| Заказ на удержании | `order_placed` |
| Заказ в обработке | `order_paid` после письма «на удержании» (банковский перевод, чек), иначе `order_placed` (оплачен сразу, оплата при получении) |
| Выполненный заказ; частичная отправка и обновление трек-номера AST | `order_shipped` (`order_completed` — для виртуальных и скачиваемых заказов) |
| Возврат и частичный возврат | `order_refunded` |
| Отменённый заказ (покупателю) | `order_cancelled` |
| Неудачный заказ (покупателю) | `order_failed` |
| Детали заказа / счёт | `invoice` |
| Заметка для покупателя | `order_note` |
| Сброс пароля, новый аккаунт | `password_reset`, `account_new` (ссылки доступа: без отслеживания кликов, OneTrace хранит только тему) |
| Письма владельцу магазина: новый, отменённый, неудачный заказ … | `admin_new_order`, `admin_cancelled_order`, `admin_failed_order` … — всегда отправляет магазин |
| WordPress: сброс пароля, новый пользователь, смена пароля и email | `password_reset`, `account_new`, `password_changed`, `email_changed`; администратору `admin_new_user`, `admin_password_changed` — всегда отправляет магазин |
| Любое другое письмо | `other` |

Вид можно поменять фильтром `onetrace_woocommerce_email_kind` (например, `email_verification` для письма плагина подтверждения адреса).

## Рекомендации и Web Push

- Виджеты из раздела **Сайт → Виджеты** платформы: укажите их идентификаторы для страницы товара и корзины в настройках или вставьте `[onetrace_widget id="k3x9…"]` в любое место. На страницах товара, категории и корзины виджет получает текущие товары.
- Web Push: включите в настройках — плагин отдаёт `/cdp-sw.js` с корня магазина (нужны постоянные ссылки), — и поставьте `[onetrace_push_button]` там, где посетители подписываются.

## Программа лояльности

Включите «Бонусные баллы» в **Настройки → OneTrace → Программа лояльности**; сама программа (начисление, уровни, доля заказа, которую можно оплатить баллами) настраивается в разделе **Лояльность** платформы, секретному ключу нужны права `loyalty.read` и `loyalty.write`.

- **Корзина и оформление** (классические страницы и блоки Cart и Checkout): вошедший покупатель видит баланс, сколько баллов можно списать и сколько начислится за заказ, вводит баллы и нажимает «Списать баллы». Баллы резервируются на платформе на 30 минут, скидка — отрицательный сбор в итогах; при изменении корзины баллы резервируются заново в пределах допустимой доли. Гостю предлагается войти.
- **Заказ:** резерв подтверждается номером заказа при оформлении; если платформа недоступна, Action Scheduler повторяет попытку. Отменённые и возвращённые заказы возвращают баллы на платформе (по событиям заказов).
- **Мой аккаунт → Бонусные баллы:** баланс, баллы в ожидании срока возврата, уровень, скоро сгорающие баллы и последние операции; «Вступить в программу» — для программ со вступлением по заявке.

Покупатель находится на платформе по `user_id` (id пользователя WordPress), как в событиях заказов.

## Конфиденциальность

- С плагином согласия, поддерживающим [WP Consent API](https://wordpress.org/plugins/wp-consent-api/), трекер загружается после согласия посетителя на статистические cookie (отключается в настройках).
- Согласие передаётся, только если покупатель отметил галочку; снятая галочка в личном кабинете — отписка.
- Уже переданные данные остаются в проекте OneTrace; профили удаляются там (GDPR).

## WP-CLI

```bash
wp onetrace test           # проверка обоих ключей
wp onetrace status         # очередь и последняя ошибка
wp onetrace flush          # отправить ожидающее сейчас
wp onetrace sync-catalog   # выгрузить весь каталог сейчас
```

## Разработка

```bash
composer install
tests/env/run.sh                                            # интеграционные тесты: свежие WordPress и WooCommerce в Docker
WP_TAG=6.8-php8.1-apache WC_VERSION=9.9.5 tests/env/run.sh  # старые версии (в tests/env сначала docker compose down -v)
vendor/bin/phpstan analyse
php bin/build.php && tests/env/smoke.sh                     # dist/onetrace-for-woocommerce.zip и проверка через cURL
```

## Выпуск

Плагин публикуется на [wordpress.org/plugins/onetrace-for-woocommerce](https://wordpress.org/plugins/onetrace-for-woocommerce/) из CI: версия в заголовке плагина, `ONETRACE_WC_VERSION` и `Stable tag` в `readme.txt`, изменения в `CHANGELOG.md` и `readme.txt` → тег `vX.Y.Z` и релиз на GitHub. После тестов сборка уходит в `trunk` и `tags/X.Y.Z` SVN wordpress.org (окружение `wordpress.org`, секреты `SVN_USERNAME` и `SVN_PASSWORD`), zip — в релиз GitHub. `readme.txt` и картинки страницы из `.wordpress-org/` обновляются из `main` без релиза.
